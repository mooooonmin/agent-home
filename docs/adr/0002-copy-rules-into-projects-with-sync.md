# 0002. 규칙·스킬·검사 도구는 프로젝트에 사본으로 넣고 sync_rules.py로 다시 반영한다

- 상태: 채택
- 날짜: 2026-11-04

## 배경

claude-home은 여러 프로젝트가 따를 규칙의 원본입니다. 클라우드 세션은 세션에 넣은 저장소의 파일만 보고 내 PC의 `~/.claude/`는 따라오지 않으므로, 프로젝트 저장소 안에도 규칙이 있어야 합니다. 예전에는 손으로 복사해서, 원본이 바뀌어도 프로젝트에 반영할 방법이 문서에만 있었습니다.

## 결정

- 프로젝트에는 사본을 넣습니다. 반영은 `scripts/sync_rules.py --target <프로젝트>`로 하고, 기본은 미리보기, `--apply`로 씁니다.
- 프로젝트 `AGENTS.md`에서는 공통 규칙 표시 사이만 바꾸고, 표시 밖의 저장소 안내는 건드리지 않습니다.
- 예전 방식의 사본은 claude-home 기록에 있던 내용 그대로일 때만 지우고, 고친 흔적이 있으면 남기고 알립니다.
- 사용자 설정(`~/.claude/`, `~/.codex/AGENTS.md`, `~/.agents/skills/`)에는 `--user`로 넣습니다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 세션 시작 때 claude-home을 받아 오는 훅 (gstack 팀 모드와 비슷) | 항상 최신 | 클라우드에서 비공개 저장소 접근과 동작을 확인하지 못함. 규칙 변경이 프로젝트 기록에 남지 않음 |
| 세션에 claude-home과 프로젝트를 함께 넣기 | 복사가 없음 | 여러 저장소를 넣으면 각 저장소의 `settings.json` 권한·훅이 적용되지 않음(공식 문서) |
| 손으로 복사 | 도구가 필요 없음 | 빠뜨리기 쉽고 예전 사본 정리가 안 됨 |

## 결과

- 규칙이 바뀐 내용이 프로젝트의 커밋으로 남아 리뷰할 수 있습니다.
- 원본을 고친 뒤 프로젝트마다 다시 반영해야 합니다. 어느 시점의 claude-home으로 반영했는지는 프로젝트의 `.claude-home-version`에 적힙니다.
