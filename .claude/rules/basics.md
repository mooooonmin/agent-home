# 기본 규칙

## 소통

- 답변과 문서는 한국어로 씁니다. 코드, 식별자, 명령어, 고유명사는 영어 그대로 둡니다.
- 결과부터 먼저 말하고, 설명은 짧게 합니다.
- 모르는 것은 추측하지 말고 확인하거나 물어봅니다.

## 작업 방식

- 큰 작업은 시작 전에 계획을 짧게 정리하고, 끝나면 무엇을 바꿨는지 요약합니다.
- 기존 파일의 형식(제목 수준, 표, 링크 방식)을 먼저 확인하고 그대로 따릅니다.

## 상태를 정확히 말하기

다음 상태를 섞지 않고, 실제로 확인한 만큼만 말합니다.

| 상태 | 뜻 |
|---|---|
| 구현함 | 코드를 작성했다 |
| 검증함 | 테스트·실행으로 동작을 확인했다 (어떤 명령으로, 어디서 확인했는지 함께 적음) |
| 배포함 | 실제 환경에 반영되고 동작을 확인했다. 푸시나 병합은 배포가 아니다 |

- 돌리지 못한 테스트, 건너뛴 확인은 "미확인"으로 적고 이유를 붙입니다. 실패나 건너뜀을 통과로 세지 않습니다.
- 로컬 통과와 CI 통과를 구분합니다.

## 비밀값

- API 키, 토큰, 비밀번호는 저장소에 절대 넣지 않습니다. 필요한 값은 환경 변수로 받습니다(클라우드는 환경 설정의 Network secrets에 등록).
- `.env`, `secrets/` 파일은 읽거나 커밋하지 않습니다.
- 업무 저장소(saint-*, sws-*)의 내부 정보는 개인 저장소로 옮기지 않습니다.
