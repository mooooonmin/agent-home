# 코딩 규칙과 설계 원칙

모든 언어에 공통으로 적용합니다. 언어별 세부 규칙은 `lang/`에 있고, 해당 언어 파일을 다룰 때 함께 읽힙니다.
**우선순위**: 저장소의 린트·포맷 설정 > 저장소 CLAUDE.md > 언어별 규칙 > 이 파일.

## 기본 태도

- 고치기 전에 주변 코드를 읽고 그 저장소의 방식(이름, 폴더 구조, 오류 처리, 테스트 위치)을 따릅니다. 새 방식을 들여오지 않습니다.
- 요청받은 범위만 바꿉니다. 관련 없는 리팩터링, 포맷 변경, 의존성 추가는 따로 제안합니다.
- 포맷은 사람이 맞추지 않고 포매터에 맡깁니다. 저장소에 포매터·린터가 있으면 끝나기 전에 실행합니다.
- 동작을 바꿨으면 테스트를 돌리고 결과를 보고합니다. 돌리지 못했으면 그렇다고 적습니다.

## 읽기 쉬운 코드

- **이름**: 무엇인지가 드러나는 이름을 씁니다. 줄임말, 한 글자 이름(반복문 인덱스 제외), `data`·`info`·`temp` 같은 뭉뚱그린 이름을 피합니다.
- **함수**: 한 가지 일만 합니다. 인자는 3개 이하가 좋고, 넘으면 객체로 묶습니다. 불리언 플래그 인자로 동작을 바꾸지 말고 함수를 나눕니다.
- **조건문**: 일찍 반환해서 중첩을 줄입니다. 복잡한 조건은 이름 있는 변수나 함수로 뺍니다.
- **매직 넘버**: 의미 있는 숫자·문자열은 이름 있는 상수로 둡니다.
- **주석**: 코드가 "무엇"을 하는지가 아니라 "왜" 그렇게 했는지를 적습니다. 주석 처리한 죽은 코드는 남기지 않습니다.

## 설계 원칙

- **단순하게 먼저**: 지금 필요한 만큼만 만듭니다. 쓰일지 모르는 확장 지점, 설정, 추상화를 미리 만들지 않습니다(YAGNI).
- **중복**: 같은 지식이 세 번 나오면 하나로 모읍니다. 겉모양만 비슷한 코드는 억지로 합치지 않습니다.
- **SOLID**: 클래스·모듈은 바뀌는 이유가 하나여야 합니다(단일 책임). 구체 구현보다 인터페이스에 의존하고, 의존성은 생성자로 주입합니다.
- **합성 우선**: 상속보다 합성을 먼저 고려합니다.
- **경계 분리**: 핵심 로직과 입출력(DB, 네트워크, 파일, UI)을 나눕니다. 핵심 로직은 입출력 없이 테스트할 수 있어야 합니다.
- **불변 우선**: 값을 바꾸기보다 새 값을 만듭니다. 공유 상태와 부수 효과는 최소화하고, 있으면 드러나게 둡니다.
- 큰 설계 결정(라이브러리 선택, 구조 변경, 저장 방식)은 ADR로 남깁니다. 방법은 `docs.md` 규칙을 따릅니다.

## 오류 처리

- 오류를 삼키지 않습니다. 잡았으면 처리하거나, 맥락을 붙여 다시 던지거나, 기록합니다.
- 입력은 경계(API, CLI, 폼)에서 한 번 검증하고 안쪽 코드는 검증된 값을 믿습니다.
- 사용자에게 보이는 오류 메시지와 로그용 상세 정보를 구분합니다. 로그에 비밀값·개인정보를 남기지 않습니다.

## 테스트

- 새 기능과 버그 수정에는 테스트를 붙입니다. 버그는 먼저 실패하는 테스트로 재현합니다.
- 테스트 하나에는 개념 하나만 검증합니다. 이름은 "무엇을 하면 어떻게 된다"가 드러나게 짓습니다.
- 구현 세부가 아니라 동작을 검증합니다. 외부 시스템만 가짜로 바꾸고 내 코드는 진짜로 돌립니다.

## 보안과 의존성

- 비밀값은 코드에 넣지 않고 환경 변수로 받습니다.
- SQL, 셸 명령, HTML에 외부 입력을 문자열로 이어 붙이지 않습니다. 매개변수 바인딩과 이스케이프를 씁니다.
- 새 의존성은 꼭 필요할 때만 추가하고, 추가했으면 이유를 작업 요약에 적습니다. 버전은 잠금 파일로 고정합니다.
