# 문서 관리 규칙

문서는 코드와 함께 바뀌어야 최신으로 유지됩니다. 나중에 몰아서 고치지 않습니다.

## 같은 커밋에서 문서도 고친다

코드를 바꿨으면 끝내기 전에 영향을 받는 문서를 찾아 **같은 커밋**에서 고칩니다.

| 바꾼 것 | 고칠 문서 |
|---|---|
| 설치·실행 방법, 환경 변수, 필요한 도구 | `README.md`의 시작하기 |
| 공개 API, CLI 옵션, 설정 키 | `docs/`의 해당 문서, 코드의 문서 주석 |
| 폴더 구조, 주요 모듈 | `README.md`의 구조 설명, `CLAUDE.md` |
| 큰 설계 결정 | 새 ADR (`docs/adr/`) |
| 사용자에게 보이는 변화 | `CHANGELOG.md`의 `[Unreleased]` |

고칠 문서가 없으면 작업 요약에 "문서 영향 없음"이라고 적습니다.

## 문서 구성

새 프로젝트는 다음 구성으로 시작합니다. 템플릿: `templates/docs/`

- `README.md`: 무엇인지, 시작하기(설치·실행·테스트 명령), 구조, 문서 링크
- `docs/adr/NNNN-제목.md`: 설계 결정 기록. 번호는 이어서 붙이고, 결정이 바뀌면 지우지 말고 새 ADR을 만든 뒤 예전 ADR의 상태를 "대체됨"으로 바꿉니다.
- `CHANGELOG.md`: [Keep a Changelog](https://keepachangelog.com/ko/1.1.0/) 형식
- `CLAUDE.md`: 이 저장소에서 Claude가 알아야 할 것(빌드·테스트 명령, 규칙, 주의점)

## 문서 쓰는 법

- 결과와 사용법을 먼저, 배경 설명은 뒤에 씁니다.
- 명령어는 복사해서 바로 실행할 수 있게 코드 블록으로 씁니다.
- 문서끼리는 상대 경로로 연결하고, 같은 내용을 여러 곳에 복사하지 말고 한곳을 가리킵니다.
- 날짜·버전처럼 낡기 쉬운 정보는 꼭 필요할 때만 적습니다.

## 자동 점검

- CI에서 깨진 내부 링크·이미지·앵커를 막습니다. 템플릿: `templates/ci/`
- 문서가 코드와 어긋났는지는 `/update-docs`로 점검합니다.
