# 번역 규칙

`*-ko` 저장소(clean-code-javascript-ko, system-design-notes-ko, Hands-On-Large-Language-Models-ko 등)에서 공통으로 지키는 원칙입니다. 저장소에 `TRANSLATION.md`가 있으면 **그 파일이 우선**합니다.

## 원칙

- **문체**: 책·안내서는 "~합니다"체, 노트는 평서체("~한다")로 씁니다. 저장소 안에서는 한 가지로 통일합니다.
- **용어**: 저장소의 용어집 → `glossary/`의 분야별 용어집 순서로 따릅니다. 처음 나올 때만 `한국어(English)`로 원어를 함께 적고, 그 뒤로는 한국어만 씁니다.
  - 한국어로 옮기면 어색한 용어(API, CDN, 캐시, 샤딩 등)는 음차하거나 영어로 둡니다.
- **고유명사**: 사람·책·제품·라이브러리·회사 이름은 영어 그대로 둡니다. 국내 번역서가 있는 책은 번역서 제목을 쓰고 원제를 함께 적습니다.
- **코드**: 코드, 식별자, 문자열 리터럴, 명령어, SQL, API 경로, 수식, 숫자는 바꾸지 않습니다. 코드 주석만 한국어로 옮깁니다.
- **구조**: 제목 수준, 목록, 표, HTML 태그, 이미지 경로는 원본과 똑같이 유지합니다. 원본 폴더명은 바꾸지 않습니다.
- **이미지**: 이미지는 원본 그대로 쓰고 `alt` 텍스트만 옮깁니다.
- **링크**: 외부 링크는 원본 그대로 둡니다. 저장소 내부 링크는 한국어 제목 앵커에 맞게 고칩니다.
- **원문 오류**: 명백한 오타는 바로잡아 옮기고, 내용상 의문이 있으면 원문 의미를 살린 뒤 작업 요약에 적습니다.
- **노트북(.ipynb)**: 코드 셀과 출력은 건드리지 않습니다. 마크다운 셀만 번역하거나, 저장소 방식에 따라 요약 셀을 덧붙입니다.

## 새 용어를 만났을 때

1. 저장소 용어집과 `glossary/`에서 먼저 찾습니다.
2. 없으면 국내 번역서나 널리 쓰는 표현을 고르고, 작업 요약에 "새 용어" 목록으로 남깁니다.
3. 확정된 용어는 저장소 `TRANSLATION.md`와 `glossary/`에 함께 추가합니다.

## 저작권 표기

- 새 번역 저장소에는 `NOTICE`(원본 저장소, 기준 커밋, 라이선스, 변경 사항)와 README 상단 안내를 넣습니다. 템플릿: `templates/translation-repo/`
- 원본 라이선스가 번역을 허용하는지 먼저 확인합니다.
