# 코딩 규칙

claude-home 공통 규칙의 일부로, 코드를 다룰 때 읽습니다. 항상 지킬 기본 태도와 우선순위는 `AGENTS.md`의 "코딩 규칙과 설계 원칙"에 있습니다. 고치려면 claude-home에서 고친 뒤 `scripts/sync_rules.py`로 반영합니다.

## 읽기 쉬운 코드

- **이름**: 무엇인지가 드러나는 이름을 씁니다. 줄임말, 한 글자 이름(반복문 인덱스 제외), `data`·`info`·`temp` 같은 뭉뚱그린 이름을 피합니다.
- **함수**: 한 가지 일만 합니다. 인자는 3개 이하가 좋고, 넘으면 객체로 묶습니다. 불리언 플래그 인자로 동작을 바꾸지 말고 함수를 나눕니다.
- **조건문**: 일찍 반환해서 중첩을 줄입니다. 복잡한 조건은 이름 있는 변수나 함수로 뺍니다.
- **매직 넘버**: 의미 있는 숫자·문자열은 이름 있는 상수로 둡니다.
- **주석**: 코드가 "무엇"을 하는지가 아니라 "왜" 그렇게 했는지를 적습니다. 주석 처리한 죽은 코드는 남기지 않습니다.

## 설계 원칙

- **단순하게 먼저**: 지금 필요한 만큼만 만듭니다. 쓰일지 모르는 확장 지점, 설정, 추상화를 미리 만들지 않습니다(YAGNI).
- **중복**: 같은 지식이 세 번 나오면 하나로 모읍니다. 겉모양만 비슷한 코드는 억지로 합치지 않습니다.
- **SOLID**: 클래스·모듈은 바뀌는 이유가 하나여야 합니다(단일 책임). 구체 구현보다 인터페이스에 의존하고, 의존성은 생성자로 주입합니다.
- **합성 우선**: 상속보다 합성을 먼저 고려합니다.
- **경계 분리**: 핵심 로직과 입출력(DB, 네트워크, 파일, UI)을 나눕니다. 핵심 로직은 입출력 없이 테스트할 수 있어야 합니다.
- **규칙은 검사로 강제**: 계층 방향처럼 지켜야 할 구조 규칙은 문서에만 적지 말고 테스트로 만듭니다. 어기면 CI가 실패해야 합니다. 아래 템플릿은 claude-home 저장소에 있습니다.
  - Java: ArchUnit (claude-home의 `templates/lint/java/ArchitectureTest.java`)
  - Python: import-linter (claude-home의 `templates/lint/python/importlinter.toml`)
  - 저장소 공통 규칙(생성물 커밋, 버전 고정, `latest` 태그, 문서 링크, 에이전트 지시 파일): `scripts/repo_checks.py` (원본: claude-home의 `templates/ci/`)
  - 검사 도구를 직접 만들었다면 그 도구에도 테스트를 붙입니다.
- **불변 우선**: 값을 바꾸기보다 새 값을 만듭니다. 공유 상태와 부수 효과는 최소화하고, 있으면 드러나게 둡니다.
- 큰 설계 결정(라이브러리 선택, 구조 변경, 저장 방식)은 ADR로 남깁니다. 방법은 `writing-docs.md`의 문서 구성을 따릅니다.

## 오류 처리

- 오류를 삼키지 않습니다. 잡았으면 처리하거나, 맥락을 붙여 다시 던지거나, 기록합니다.
- 입력은 경계(API, CLI, 폼)에서 한 번 검증하고 안쪽 코드는 검증된 값을 믿습니다.
- 사용자에게 보이는 오류 메시지와 로그용 상세 정보를 구분합니다. 로그에 비밀값·개인정보를 남기지 않습니다.

## 테스트

- 새 기능과 버그 수정에는 테스트를 붙입니다. 버그는 먼저 실패하는 테스트로 재현합니다.
- 테스트 하나에는 개념 하나만 검증합니다. 이름은 "무엇을 하면 어떻게 된다"가 드러나게 짓습니다.
- 구현 세부가 아니라 동작을 검증합니다. 외부 시스템만 가짜로 바꾸고 내 코드는 진짜로 돌립니다.

## 스크립트와 도구

- 데이터를 지우거나 바꾸는 스크립트는 **기본이 미리보기(dry-run)** 입니다. 무엇을 바꿀지만 출력하고, `--apply`를 붙였을 때만 실제로 실행합니다.
- 실행 결과, 로그, 측정값, AI가 만든 산출물은 저장소에 커밋하지 않습니다. 루트의 `tmp/`, `logs/`, `outputs/`나 CI 아티팩트에 두고, 필요하면 문서에서 위치만 연결합니다.
- 자주 쓰는 검사·운영 명령은 `scripts/`나 `tools/`에 모으고 그 폴더 README에 용도를 표로 정리합니다.

## 보안과 의존성

- 비밀값은 코드에 넣지 않고 환경 변수로 받습니다. 필요한 변수 목록은 값 없이 `.env.example`에 적어 커밋합니다.
- SQL, 셸 명령, HTML에 외부 입력을 문자열로 이어 붙이지 않습니다. 매개변수 바인딩과 이스케이프를 씁니다.
- 새 의존성은 꼭 필요할 때만 추가하고, 추가했으면 이유를 작업 요약에 적습니다. 버전은 잠금 파일이나 `==`로 고정합니다.
- 컨테이너 이미지는 `latest` 대신 고정 버전 태그를 씁니다.
